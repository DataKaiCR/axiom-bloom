# Axiom Bloom Open Source Posture

## Public Surface

Axiom Bloom's complete application source is public under the MIT License. The original concept was first published in 2023; licenses already granted for distributed versions are perpetual and cannot be withdrawn.

This repository is an experimental DataKai creative project. It serves two purposes:

1. Provide a polished, freely usable L-system art studio for creative coders and generative artists.
2. Dogfood DKOS and dkkernel governance against a real TypeScript/Svelte application so protocol quality is measured beyond Python repositories.

## Commercial Posture

Axiom Bloom has no paid attach and is not counted as an open-core acquisition channel. Its value to DataKai is public craftsmanship, technical learning, and governance evidence. Adoption, stars, or outside contributions are not treated as revenue evidence.

If a commercial layer is proposed later, it requires a separate review naming the paid value, attribution mechanism, operating cost, and fork-resistant advantage.

## Support Boundary

Public support is best-effort and capped at one founder hour per week averaged over eight weeks. There is no response-time commitment, compatibility guarantee, private implementation assistance, or service-level agreement.

Issues may be closed when they exceed the project's scope or support budget. Security reports and reproducible defects take priority over feature requests.

## Fork and Reversibility Accounting

The MIT license permits use, modification, redistribution, and resale. A fork can reproduce the public application; DataKai claims no code scarcity or commercial exclusivity.

DataKai can stop publishing future versions or freeze maintenance, but cannot revoke rights already granted. The Axiom Bloom and DataKai names, logos, and visual identity are not granted by the software license.

## Platform Resilience

The core application has no LLM or hosted-service dependency. It builds into static assets and runs locally in a modern browser. Development dependencies are replaceable and do not control access to exported artwork.

## Evidence to Track

The experimental posture is reviewed using observable evidence:

- Founder time spent on public support and maintenance
- External installations and completed artwork exports
- Reproducible defects versus feature requests
- Outside pull requests and the review time they consume
- DKOS findings by language, rule, false-positive rate, and unsupported file type

A support average above one hour per week for four consecutive weeks triggers scope reduction or a maintenance freeze.
